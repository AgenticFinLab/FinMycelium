# 5 · 检查、结果状态与输出

导航：[总览](0-overview.md) · [图协议](2-graph-contract.md) · [执行与恢复](4-execution-and-recovery.md)

## 5.1 检查层次

各步先做局部检查，最后核对整图。不把 JSON 可解析、文件已生成或 Gantt 可显示当作内容审核通过。

| 类别 | 程序可核验的要求 | 不能由此保证的内容 |
| --- | --- | --- |
| 输入 | 身份、范围、sample、来源映射与哈希一致 | 研究计划已覆盖人物全部重要事项 |
| 协议 | 必填字段、类型、枚举与协议标识 | 字段中的自然语言都正确 |
| 身份与引用 | ID 唯一、端点存在、层级引用有效 | 现实中的主体归属一定正确 |
| 层级 | 至少一个 Stage、每个 Stage 至少一个 Phase、Action 唯一归属、层级引用和有据排序 | Stage/Phase 划分最合理 |
| 时间 | 已知区间的包含/不重叠约束、原始先后冲突记录、`P_consistent` 无环及其传递闭包 | 未知时间已被解决、窗口相交代表同时 |
| 证据 | 来源对应、引文偏移、原文哈希与支持引用有效 | 引文确实支持模型写出的命题 |
| 上下文 | 六种关联类型、实体引用、已知时序矛盾 | 人物动机或当时认知被证明 |
| 工作覆盖 | 已知来源元数据保留、实际交接与处理区间、事实去向、未完成项 | 获取全文即读完全文、现实世界中的事件已完整穷尽 |

具体规则：

- 相同 ID 指向多个对象、悬空引用、必需归属缺失、没有 Stage 或某 Stage 没有 Phase 属于结构错误。单动作或空动作 Phase 需要说明原因。
- 检查 Stage/Phase 起止边界理由及有据顺序。相关端点均已知时核验 Phase ⊆ Stage ⊆ Event、同级不重叠；未知端点标未验证。真实持续 Action 应位于其唯一 Phase 内；粗发生窗口仅要求与所属 Phase 有交集且归属有据，跨界且归属未定的候选不能伪造拆分。确定的层级/归属矛盾报告错误。
- 检查原始先后主张的双向冲突、环及与已知时间的矛盾；有证据的分歧完整记录且从 `P_consistent` 排除时为 warning，不要求模型消灭来源冲突。漏记冲突、擅自删主张、冲突边进入可用顺序视图或该视图仍成环属于 error。语义环、无边的 Action 和不连通图不因此报错。
- 检查传递闭包后再判断顺序是否未知；有先后路径却仍无说明地标 `order_unknown` 是不一致。端点不全或时间前提有未决冲突时，生成 `derived` 区间关系属于 error。
- 已知行为对象、职务/代理身份、参与实体和角色必须从事实记录保留到图。程序核对条件字段与已有记录，语义上是否本来就能识别仍须审核；未知可按协议附 Gap。ContextRef 不得仅按 Context ID 和类型去重而丢失参与者或适用限制。
- `matched` 引文必须逐字与冻结 sample 对应。未定位候选可以留在事实检查点，但若作为有效 `O/A` 支持发布则报告错误；不得悄悄改写 quote 或伪造偏移。
- 明确缺证的描述允许 `support: []` 与 Gap。已有引用却不符合类型/定位规则，不能用一条 Gap 掩盖无效引用。
- Phase 基准的缺失类别、未知时间、冲突与疑似语义问题进入审核提示，不自动强制重新构建。
- 尚未归属的动作、未处理材料或必要步骤失败不能通过隐藏对象而变成“完成”。

## 5.2 `checks.json`

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `run_id` | string | 绑定本次运行 |
| `input_sha256` | string | 绑定确切输入文件 |
| `graph_sha256` | string \| null | 绑定确切图文件；没有图则为空 |
| `artifact_hashes` | object | 本报告引用的其他输入/事实文件的哈希 |
| `summary` | object | `checked`、`not_checked` 两个检查类别数组，`errors`、`warnings` 计数 |
| `issues` | Issue[] | 每个具体问题 |
| `review_required` | boolean | 构建草稿为 true；不由结构检查改成内容审核通过 |

`Issue`：

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| `code` | string | 稳定、可汇总的问题编码，如 `ACTION_PHASE_MISSING` |
| `severity` | enum | `error / warning / info` |
| `artifact` | enum | `input / facts / graph` |
| `object_type / object_id` | string | 定位对象；输入或整个根对象可使用其 run/任务 ID |
| `field` | string | 对象内字段路径；不以根数组下标代替对象身份 |
| `message` | string | 问题、未知或未检查原因 |
| `evidence_ids` | string[]，可选 | 便于复核相关引文 |

`error` 表示已确定的协议、结构、引用或执行完整性问题，阻止声明完整草稿；`warning` 表示缺口、冲突或需要内容判断的风险；`info` 表示范围说明和未验证信息。语义启发式发现的“可能错误”不能伪装成确定的事实错误。

`not_checked` 明确列出未执行或无法程序保证的检查，如 `semantic_support`、`real_world_completeness`。零 error 不等于这些检查已通过。原文定位与语义支持应分别报告。

运行文件哈希均针对最终写盘的确切字节计算 SHA256；sample 哈希针对 UTF-8 `content` 计算。序列化格式变化会改变文件哈希，需同步更新引用，不能拿另一份 JSON 的哈希冒充当前图。

## 5.3 运行、结果与展示状态

运行记录将三个状态分开保存：

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `execution_status` | `ready / running / finished / limit / interrupted / failed` | 是否执行中，以及为何停止 |
| `result_status` | `none / partial / draft` | 无可用结果、部分结果、结构完成的草稿 |
| `render_status` | `not_started / completed / failed` | Gantt 是否生成 |

界面可以映射为现有任务状态，但不能丢掉上述区别：

- **草稿完成**：必要步骤完成、材料处理与事实去向有记录、完整图要求通过。未知、Gap、Conflict 和内容审核提示允许保留；仍是 draft。
- **部分完成**：已有事实或图可保存，但必要步骤、材料处理、动作归属或结构要求尚未完成。检查中列出未完成项，不宣布已符合完整图协议。
- **失败**：输入或运行错误使本次不能继续；若已有有效部分结果，仍保存为 partial，而不是删除成果。

额度停止或中断是执行原因，不必然意味着没有结果。绘图失败不使有效图退回未构建状态。内容验收是独立的后续流程，不能由 `execution_status=finished` 推出。

## 5.4 输出目录与资产对应

| 入口 | 默认输出根目录 |
| --- | --- |
| Interface / 工作台 | 配置的 `EPG-dataset/output/` |
| CLI、脚本、直接调用 | `FinMycelium/output/` |

入口确定根目录并交给同一构建逻辑；工作台不能悄悄回退到正式成果目录。目录应被 Git 忽略。以下是目标运行资产布局，编号用于区分执行尝试，不是研究计划版本：

```text
<output_root>/builds/<run_id>/
  input.json                # 已确认的确切任务正文
  config.json               # 实际构建配置，不含密钥
  provenance.json           # 输入哈希、来源版本、交接与定位映射
  state.json                # 三类状态、累计调用、检查点及当前产物引用
  checkpoints/              # 可复用的有效步骤结果
  attempts/<attempt_id>/
    facts.json              # 本次统一事实快照及 pending/lineage
    epg.json                # 有图时保存；可为明确标识的部分结果
    checks.json             # 对应本次输入、事实和图
    gantt.html              # 有可展示图时据此生成
    steps/                  # 步骤输入/响应与局部检查记录
```

可以复用现有运行存储组织这些逻辑资产，但输入、图、检查与图表必须有无歧义的一一对应。`state.json` 指向当前采用的尝试及其文件哈希；恢复保留前次产物，不覆盖成一份无法追溯的“最新文件”。图改动后重新生成检查和 Gantt，禁止展示来自另一尝试的旧图表。

完整原文可以保留在现有公共搜索存储中，以本地引用和哈希关联，无需复制大证据树；应保存实际交接正文以便复查当前构建。来源详情和运行汇总分开显示来源获取情况、实际交接范围、已处理/未处理区间，分别从 Source、`provenance` 和步骤记录读取；缺少记录时显示未知，不能将“全文已获取”显示为“全文已读”。完整处理交接正文不要求处理原始来源全文。只有图、引文和来源清单时可以独立阅读描述，实际阅读范围和完整定位复核仍可能需要运行输入或原文归档。

构建过程不写入 `EPG-dataset/person-epg/` 的正式成果，不将主表标为内容审核通过。后续收录仅选定关键结果与审核记录，运行原文、缓存、数据库和调用日志继续留在忽略目录。

## 5.5 单 Event Gantt

绘图器读取固定 `epg.json`，按 Event → Stage → Phase → Action 展开，不折叠、不再次调用模型组织事实。展示时间、行为名称、阶段边界、必要关系和上下文，提供对象 ID、来源引文、支持模式与缺口的查看入口。

已知发生窗口与持续区间需有所区分，未知时间单独显示，不能画成虚构日期或完整持续条。关系类型和方向来自图；只作显示裁剪时应让读者知道有未展示内容，不得改写 JSON。图表或对应运行记录保存源图哈希。

部分结果可绘制已存在内容，但必须提示未完成/待归属事项；不能把隐藏未完成对象的图当成完整成果。人物总图不在本轮单 Event 绘图协议内。
