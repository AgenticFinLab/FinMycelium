# 0 · 人物 Event 可视化设计

本目录规定一份人物 Event 图如何呈现为独立 HTML。读者通过 Stage 导航进入一个 Phase，先看焦点人物做了哪些事、哪些行动能确定先后，再沿关系、背景和引文查到依据。规则适用于各类人物和 storyline。

## 0.1 三份设计各回答什么

| 文档 | 负责的问题 | 绘图时如何使用 |
| --- | --- | --- |
| [人物 Event 结构设计](../person-event-structures/0-overview.md) | Action、偏序、Context、证据分别意味着什么 | 决定一个视觉符号可以表达什么事实 |
| [人物 Event 构建器](../person-event-builder/0-overview.md) | 事实、时间、关系、归属和支持记录怎样保存在图中 | 决定可以读取哪些字段，遇到缺失或冲突时保留什么 |
| 本目录 | 同一份图应当怎样分页、排卡、连线和追溯 | 决定时间位置、行、线、图例与交互的可检验行为 |

日常预览、导出和命令行操作见[交互图使用说明](../workflows/person-event-visualization.md)。图对象及字段以[图数据协议](../person-event-builder/2-graph-contract.md)为准。

遇到布局取舍时，按三个层次决定。第一，保留原图对象、方向、证据和未知。第二，让读者能分辨已知先后、实际持续和可能发生的范围。第三，才在可行位置中缩短连线、减少交叉和空白。像素、字号和具体折线路径可以优化，前两层是验收约束。

## 0.2 阅读顺序

| 章节 | 主要决定 |
| --- | --- |
| [1 · Action 的时间与排布](1-action-layout.md) | 哪些先后可以进入布局，何时排成一行、何时上下分支，重叠和未定如何区分 |
| [2 · 关系、参与者与 Context](2-relations-and-context.md) | 箭头端点和方向，跨页关系，背景的作用范围及多行时的连线 |
| [3 · 页面、证据与视口](3-view-and-evidence.md) | 页面归属、引文与来源、首屏适配，以及预览和导出的对应 |
| [4 · 图例与视觉标记](4-visual-legend.md) | 整页卡片、简称、配色、边框、各类箭头、实线、虚线、证据点线及交互状态 |
| [5 · 示例与验收](5-examples-and-checks.md) | 时间排布示例，以及对卡片、连线、证据、视口和导出逐项核对的用例 |
| [6 · 尚待决定的展示细节](6-open-questions.md) | 有多种画法的情形、当前行为及供讨论的选择 |

第一次看图，可先读第 4 章的图例，再用第 3 章从一个字段追到原文。维护自动绘图器时，先按第 1、2 章确定哪些对象和连接应出现，再用第 5 章检查实际页面。

## 0.3 从图数据到画面

1. 读入 `epg.json`，以稳定 ID 建立对象和关联索引。Stage 和 Phase 沿用图中归属，一个 Action 只在所属 Phase 出现一次。
2. 在整个 Event 上计算可用的先后约束，再投影到当前 Phase。保留每项位置的依据、仍无法比较的对象和未决冲突。
3. 先确定 Action 的时间范围、列与行，再放置本页的 Context、参与者和关系标签。缩放或打开详情只更新屏幕坐标。
4. 按字段展示 Support、Evidence 和 Source。绘图读取已有事实，独立导出无需模型或网络。同一份图可重新绘制，图中的时间、关系、ID 和审核状态都由原记录决定。

## 0.4 自动绘图的适用范围

构建完成时生成的 HTML、工作台预览与下载、对已保存图的离线重绘，共用同一套 Phase 排布。日历时间、单侧界限及已确认的先后约束决定行动可以放在哪里。只有 Phase 归属的行动仍在同一行动区内上下排。先排完整行动组，再将关联背景放到组外或符合条件的横向空位。每个 Phase 独立适配首屏，缩放保留逻辑行列。

第 1 章给出排布规则，第 2 至 4 章说明连线、证据和读图方式，第 5 章给出可重放的用例。第 6 章记录尚待选择的细节。显式手工布局沿用作者提供的坐标。人物总图另行设计。[时间与偏序](../../finmy/person_epg/event/chronology.py) · [行动分行](../../finmy/person_epg/event/action_layout.py) · [页面布局](../../finmy/person_epg/event/graph_layout.py)
