# 1 · Action 的时间与排布

[总览](0-overview.md) · [连线规则](2-relations-and-context.md) · [示例与验收](5-examples-and-checks.md)

横向表达有依据的时间或相对先后，纵向容纳分支、重叠与先后未定的行动。上下位置只为阅读服务。两张卡是否同时发生、是否存在因果关系，均须回到图中各自的记录。[动作图第 2.4–2.5 节](../person-event-structures/2-action-graph.md) · [形式化模型第 8.3 节](../person-event-structures/8-formal-model.md)

## 1.1 哪些依据可以决定先后

| 依据 | 排布规则 |
| --- | --- |
| 有效的 `precedes` | 按图协议形成 `P_consistent`，取传递闭包。`observed / asserted / derived` 的有效主张可以参与。中间行动可位于另一 Phase，页面只展示本页成员。 |
| 两个可比较且完全分离的时间窗口 | 两方起止均已知、时间框架可比、无未决冲突时，前者的排他终点不晚于后者起点，可以左右排序。即使图中没有直接关系，也可显示这一位置依据。 |
| 同一天的细时间 | 使用证据确认的最细粒度。在同一当地时间框架内，上午先于下午，下午先于晚间。有明确偏移量的时钟先统一比较。时钟与文字时段混合时，使用已有时间规则能确认的先后。原文“下午”不会得到一个虚构的钟点。 |
| `basis=inferred` 的 `precedes`、过程关系及其他关系 | 按记录显示关系与依据。它们自身不进入确定先后，包括 `responds_to`、`triggers`、`continues`。`overlaps` 和 `order_unknown` 也不提供先后。 |
| 日期缺一端、时区不可比，或记录有冲突 | 保留可说明的界限、原文和相关证据。缺一端的区间不参加区间先后推导。有独立证据支持的相对先后仍可使用。 |

构建器负责把日期锚点、原文、精度及推断支持写入图，例如原刊“昨晚”的锚点与 `I` 类依据。绘图器使用这项记录。旧图只有日精度时，可沿用现有显示兼容规则，在原时间措辞与能定位、支持该字段的引文一致时细分时段。转载、抓取或更新时间，以及 URL 内看似日期的数字，单独都不足以给行动定时。[时间协议第 1.4 节](../person-event-builder/1-input-and-facts.md)

正式偏序 `≺` 只来自图协议规定的 `P_consistent`。布局还可利用上表中的可比时间。两者共同约束卡片位置，详情应能区分“据行动时间”和“据先后路径”。结构设计中的 `a ∥ b` 表示二者在该偏序下不可比。绘图可以另有日期依据，也可能仍然没有先后依据。传递路径、时间刻度与左右位置均不产生新的可见关系边。[图数据协议第 2.5 节](../person-event-builder/2-graph-contract.md)

## 1.2 时间轴与精度

时间轴按本页有意义的日期、时段或时刻设置刻度。同一天可展开“下午／晚间”，相距数年也可相邻显示。间距取决于文字与连线需要，不表示实际经过的时长。页面保留每项时间的原始精度。

不同来源的时钟或文字时段只能定位到同一列时，保留各卡的原时刻，公共刻度提示 `See individual action times`。两张卡共享一列可以表示证据尚不能细分它们的位置；要确认同一时刻，仍需核对时区和精度。

| 行动时间的含义 | 卡片及时间标记 |
| --- | --- |
| 已知发生于一个时段或时刻 | 卡片对齐相应刻度。同一时段内有确定先后时细分相对位置。只有同一时段时可上下排。 |
| 只知某天、某月、某季度，或一个较宽的发生窗口 | 用范围括线表示“可能发生于此范围”。卡只出现一次，置于这一范围的独立行或共享行，内容中保留原精度。例如只有日期的行动横跨该日的时段区，不能因排在晚间旁边就被读作晚间发生。 |
| 已知是持续区间 `kind=duration` | 用有明确起止标记的持续线表示实际跨度，视觉上区别于发生窗口的括线。两个有据持续区间相交时分行显示，各自保留边界。开始较早不等于整个行动先于另一行动。 |
| 只有相对顺序 | 有可定位的前驱、后继时，按有据方向排布。两端都在外页时，可用两个有据锚点夹定相对位置。只有一个外页锚点时，本页卡片写明如 `After A21`，保留这项相对关系及其原端点。仅有内部先后的行动链按自身顺序展示。 |
| 只有单侧日历界限 | `By …` 卡片放在界限刻度左侧，虚线向右封到该刻度。`From …` 在右侧，虚线向左封到刻度。同一界限且彼此先后未定的行动可同列上下排。界限日期本身也可能是行动发生日。日期内有多个有据时段时，单侧卡放在这些时段的开放一侧。有独立先后依据时，先满足该顺序，再安排卡位。排他的截止日按原精度换算，例如日精度的 `end=2013-03-27` 显示 `By 26 Mar 2013`。 |
| 只有 Phase 归属 | 在同一行动区上下排，卡片写 `Phase only`。淡虚线横跨本页逻辑列，标示可查阅该行动的 Phase。Phase 本身有据的起止可在时间轴提示中查看，Action 仍保留自己的空时间字段。 |
| 存在未决先后矛盾 | 在涉及位置标明 `Order disputed`，可查看矛盾双方及依据。仍有独立证据支持的粗时间可继续显示。 |

日期精度与事实持续时间是两件事。比如两项捐赠都只知道“发生于 6 月”，可以同列上下排，不能画出持续整月的实线。若一项行动跨月持续，另一项行动在其中某天发生，可以展示它们的已知时间位置。只有原图记录了 `overlaps` 时才绘制这条关系线。若来源明确断言两项行动时间重叠、但均无可定位日期，仍可展示这条关系，轴上留作未定位。

已有草稿可能写了 `duration`，但引文只能核对两端日期。这时用点状括线保留有据的日期范围，标明 `Duration unverified`。详情仍可回查原记录；当 `/time` 或 `/time/kind` 的支持覆盖持续性时，才画持续实线。

粗粒度行动的卡片标题可以在括线内居中，时间含义由括线两端表达。图例应同时给出“可能发生的范围”和“实际持续”两种线形及英文文字。对于同日但未细分时段的行动，标明 `Time within day unresolved`。对于只知某月的行动，同理保留到月。卡片中心没有“最可能发生于此时”的含义。

## 1.3 列和行的生成顺序

1. **固定成员和依据。** 先在 Event 范围整理有效先后路径、时间比较和冲突，再取本 Phase 的 Action。出现冲突环时，隔离处于环内的约束并保留原主张，避免剔除一条边后随意定序。环外有独立依据的先后照常排布。
2. **先找可落的位置。** 分别查行动自身的发生窗口、单侧界限和已确认的前驱或后继。日期只在完整受支持的时间窗口之间产生确定先后。其余行动按所知信息定位或沿同一轴上下排。轴旁的卡片间距和行号均不表示时间差。
3. **安排同列与分支。** 同一可用时间范围内，先后能比较的行动从左向右排。可在同一位置阅读且彼此不可比的行动可以占同一列、各用一行。共同前驱后的分支、共同后继前的汇合优先这样画。缺一条边或恰好处于同一拓扑层，本身都不足以把不同日期的行动并列。同列而无重叠依据时，明确提示先后未定。同一时刻精确到分钟的两项记录，也不能凭这一分钟内的位置定序。
4. **处理区间交错。** 相交但不相同的范围各保留自己的边界，需要时用独立行。即使 A 的窗口与 B 相交、B 又与 C 相交，只要 A 的窗口完全早于 C，A 与 C 的可见先后仍须保留。不能把三者合并成一个“同时”组。
5. **在可行位置内选行。** 一条可比的行动链优先沿一行延续，有可用空间时汇合点可回到主行。并列项先沿用可接续的前驱行，其次取自上而下首个能完整容纳卡片与范围标记的空行。如果条件仍相同，采用冻结图内 Action 的原有次序，仍需区分时按稳定 ID 排列。这个次序只决定上下位置，不参加时间比较。
6. **最后布背景与线。** 先完整排好全部 Action，再将专属 Context 放在行动组外围。条件、触发、约束在上，结果在下。只有跨两项行动的结果兼条件可以使用原有横向空位，条件见[背景放置规则](2-relations-and-context.md)。同列上下比较的行动之间始终留给行动本身与时间标记。窗口变窄、缩放和打开详情均保留逻辑行列。

同一 Phase 可以同时出现单行链、上下分支和未定位行动。两个不连通的行动链如果有共同日历锚点，就共享时间轴。若各自只有相对顺序，应分别保留为相对链，避免把一条链的“第二步”画成与另一条链的“第二步”同一时刻。

生成日历刻度时，先保留同一时间框架中有材料覆盖的区间边界，再选取能相互排序的刻度。每项行动保留与这些刻度相容的跨度。清楚定位的行动优先占行，较宽的范围只有在一整段都空闲时才复用该行。同一刻度内有可靠先后时，按前驱另分小列。没有日期的独立相对链从左侧起排，每一步进入满足已知前驱的最左列；各链有自己的起点。区间首尾相接时，按协议的排他终点比较。共享一个模糊时段的记录保留原精度。

两列之间可能同时有已排序和仍不可比的行动对。读者应按所选两项的依据判断。上下位置、卡片在宽范围内的中心、独立相对链之间的水平对齐，都只服务于阅读。

## 1.4 读者能够复核的内容

选中 Action 可读取原始时间措辞、字段支持和本页的可比对象。`Earlier / Later` 中的 `dated windows` 表示两项自身的有据时间能直接比较，`order path` 表示要经由先后路径。必要时可沿 `Recorded precedence steps` 打开原关系及其端点，查到跨页的中间行动。日历范围和持续区间的详情列出原始边界，分支与未知先后保留相应提示。

## 1.5 构建器交给绘图器的内容

| 要表达的内容 | 构建记录 | 绘图时怎样使用 |
| --- | --- | --- |
| 行动属于哪里 | Action 的 `phase_id` | 决定在哪一页画这张卡。页签次序和 Stage 边界不提供行动的日内先后。 |
| 何时发生、是否持续 | `time.text / kind / start / end`、边界精度及其字段支持。有据时可附 `intraday / utc_offset`。 | 按实际精度定刻度，区别发生窗口与持续区间。日期锚点和推断理由可经字段查阅。 |
| 哪些行动有先后 | 有据关系的两个端点、`type / basis`、支持与前提；未决矛盾保留在原记录中。 | 利用有效的 `precedes` 路径；过程线沿原谓词绘制。只有能够定位的日期或相对次序才影响排布。 |
| 位于何行何列 | 由绘图器对上述记录计算 | 行列、像素坐标和标签位置属于视图；重新绘图可验证这些变化。新材料是否实际带来更细的时间或新的有据关系，须用新构建检验。 |

字段定义与构建职责分别见[事实输入](../person-event-builder/1-input-and-facts.md)与[图数据协议](../person-event-builder/2-graph-contract.md)。实现入口见[时间依据](../../finmy/person_epg/event/chronology.py)、[行动行列](../../finmy/person_epg/event/action_layout.py)和[图面分区](../../finmy/person_epg/event/graph_layout.py)。
