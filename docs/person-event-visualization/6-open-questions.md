# 6 · 尚待决定的展示细节

[总览](0-overview.md) · [视觉图例](4-visual-legend.md) · [验收用例](5-examples-and-checks.md)

以下各项在对照原生 HTML、图数据协议和既有样例时仍有可选做法。每项先说明当前行为，再给出建议和可以用来决定的情形。建议尚待确认，不作为当前验收条件。Action 分行、Evidence 与 Sources 分区、共享背景按关联继承，均已在前章确定。

## 6.1 有来源断言但先后有争议的关系线

**已经明确。** 紫线的实虚表示带有何种依据或是否为 `order_unknown`。时间刻度和详情可以提示 `Order disputed`。若两份来源断言相反顺序，原记录可保留两条 `asserted precedes`，退出确定排序，两条线仍按 `asserted` 使用实线。[关系协议](../person-event-builder/2-graph-contract.md) · [时间与排布](1-action-layout.md)

**待决定。** 是否在受争议的关系标签旁额外写 `Disputed`，并可从那里直接查到冲突双方。建议保留既有线型，仅在确实被记录为争议的关系上加文字。验收时可让读者只从关系线进入，看能否分辨“来源明确作过断言”和“目前能确定这项先后”。

## 6.2 一段引文在整个 Event 中的全部用途

**已经明确。** 字段可以查到其 Evidence，Source 可以列出本 Event 的引文。选择一段 Evidence 可看到本页有关端点或关系的高亮，并在详情读到原文和 Source。当前 Evidence 详情没有逐条列出所有 Phase 的被引字段。[字段与引文导航](../../finmy/person_epg/event/graph_inspector.js)

**待决定。** 审核时是否需要从一段引文直接反查所有引用它的 Action、Context 和 Relation 字段。建议在确有复用时，在引文详情中按对象和字段列出用途，标明所在 Phase；同一依据用于冲突备选说法时保留该限定。这样可以从一处原文核对两页的陈述，无需跨整张图常驻绘线。可用“一份访谈里的同一句话被两个 Phase 引用”检验是否值得加入。

## 6.3 当本页没有 Evidence 区时，连线图例放在哪里

**已经明确。** 合法的部分图可以有 Action 和关系，但本页没有可列出的引文。当前通用连线图例随 `Evidence` 区标题创建，所以这种页仍有紫色、蓝灰或赭色的线，页上却没有相应线型说明。Context 自身的范围和类别图例有独立入口。[自动页面](../../finmy/person_epg/event/graph.html)

**待决定。** 让连线图例始终跟随主图，还是只在没有 Evidence 区的页面移到主图。建议保留平常的阅读位置，对“有结构线、无 Evidence 区”的页面在主图区补一个同款图例。一页显示一次，空的 Evidence 区无需为图例而出现。
