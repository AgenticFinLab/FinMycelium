## 九份交接实际包含什么

“候选”是任务内去重的来源，含种子。“读到”要求读取工具确实返回正文片段；仅缓存预览、尝试后被拒都不计。“完整材料”指进入组装的来源池经清理后、最终选段前的可用文本，包含最终可能整份漏选的来源；部分网页只取得部分正文。“交接字符”取 `builder_input.json` 的 `samples[].content` 长度之和，含出处等信息；“原文字符”按选中的原文块或字符区间计算，已逐段核对能在交接中找到。篇幅和首页标题的相关性均不足以判断人物行动覆盖。

三个可以定位的例子决定了修复顺序。

- **资料未被发现。** 高盛 C 的伯克希尔 2013 年第三季度季报未进入 A、B 的候选池。若问题是核实“实际收到”，应优先查行动之后的披露。对现有候选做任何重排都找不回这份文件。
- **正文已缓存，Agent 没有读。** 公益 C 已取得 Forbes 对电话招募的报道 `56b58c`，却未执行正文阅读。这里适合比较“先读哪些来源”的策略。返回更多网页或只在最后放宽字符预算都不能直接解决。
- **已经读到，最终没有交付。** 高盛 B 的修约公告 `356d70` 含巴菲特本人谈继续持仓的原话；公益 B 的回顾 `ffd24b` 含 12 月回应。两处都出现在 `read_source` 返回的原文里，都没有对应的原文标记。两份正式交接都留有大量字符余量。小范围补选这类段落，比把所有长文扩大到 90,000 字符更有针对性。
