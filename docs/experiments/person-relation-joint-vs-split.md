# 关联阶段优化实验

更新日期：2026-11-18

本实验比较证据供应、关系发现和职责拆分对事件图构建的影响。任务是重建巴菲特投资高盛的过程：为人物行为（Action）关联背景与条件（Context），并提取行为之间的关系。

## 结论

**采用均衡证据供应和完整关系审查，继续联合执行 Context 关联与关系发现。撤回职责拆分方案。**

| 方法 | 目标 | 实验结果 | 决定 |
|---|---|---|---|
| 均衡证据供应 | 让每个 Action 都获得直接证据 | 首批证据覆盖从 22/26 提升至 26/26 | 保留 |
| 主动关系发现与完整审查 | 减少遗漏，完成全部 Action 的关系检查 | 关系从 7 条增至 10 条，完成 26/26 个 Action 的审查，结果从 partial 变为 draft | 保留 |
| 职责拆分 | 通过分开 Context 关联与关系发现，缩短执行时间 | 耗时增加 19.6%，两次超时，Context 阶段仍未完成 | 未达到提速目标，撤回 |

## 实验设置

所有运行从同一份组织完成后的快照开始，上游搜索、事实抽取和事件组织结果固定。改进依次叠加：基线 → 均衡证据供应 → 主动关系发现与完整审查 → 职责拆分。

| 配置 | 设置 |
|---|---|
| 事件 | Goldman Sachs crisis investment |
| 模型 | `ark/kimi-k3-1-pro-261024` |
| 输入快照 | `PBUILD-dee74d7e4a1d_organization-snapshot.json` |
| 总调用上限 | 60 |
| 单次输出上限 | 65,536 tokens |
| 上下文字符上限 | 240,000 |
| 读取超时 | 900 秒 |
| 补读上限 | 40 次、96,000 字符 |
| 最终组织修复 | 关闭 |

拆分方案先执行 Context 关联，再执行关系发现；Context 阶段最多使用 30 次调用、20 次补读和 48,000 字符。本次运行未触及这些阶段上限。

## 改进分析

### 均衡证据供应：补齐证据覆盖

先为每个 Action 提供至少一条直接引用的完整证据，再轮流补充其他证据，共享证据只发送一次。历史运行的首批证据覆盖从 22/26（84.6%）提升至 26/26（100%）。

这一改进消除了部分 Action 有证据却未收到证据的情况。运行产出从 6 条关系增至 7 条，调用次数从 8 次减少到 5 次；总耗时没有下降。保留该方法，主要收益是证据覆盖完整。

### 主动关系发现与完整审查：增加关系并完成流程

要求模型主动检查 Action 之间及跨 Phase 的关系，并逐 Action 记录审查结果。实现同时加入关联字段的局部纠错机制；本次运行未触发纠错。

原有 7 条关系全部保留，新增 3 条时序关系：

- 2008 年投资 → 2009 年年度披露。
- 2009 年年度披露 → 2010 年年度披露。
- 2011 年赎回预期 → 收到偿还款。

全部 26 个 Action 完成关系审查，结果由 partial 变为 draft。保留该方法，主要收益是关系发现和流程完成度。

### 职责拆分：提速失败，撤回

拆分的目标是降低单次任务负担、缩短执行时间。联合方案用 37.14 分钟完成；拆分方案累计调用 44.41 分钟，增加 7.28 分钟（19.6%），仍未完成 Context 关联，关系发现阶段没有启动。

| 调用 | 耗时（分钟） | 结果 |
|---|---:|---|
| 首次 Context 调用 | 18.49 | 读取超时，无正式结果 |
| 续跑后的 Context 调用 | 4.58 | 成功请求补读材料 |
| 补读后的 Context 调用 | 21.34 | 再次读取超时，无正式结果 |

职责拆分后，首个任务仍处理 26 个 Action、4 个 Phase，输入约 50,212 tokens，与联合方案的 50,163 tokens 接近。任务职责减少了，单次请求规模几乎未变。两次超时后没有提交任何图更新，最终图与输入快照一致。

**该方案没有实现缩短时间的目标，且阻塞了后续关系发现，因此撤回，恢复联合执行。**
