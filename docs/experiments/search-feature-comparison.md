# 搜索功能演进与效果对比

2026-11-23。围绕巴菲特参与高盛危机投资这一任务，比较交易条款、人物决策及赎回和权证结算证据的交付质量与成本。当前保留 **精简实现＋BM25**，仓库配置默认启用 BM25 段落检索。

## 功能改动

| 方案名称 | 对应改动 |
|---|---|
| **基础选材** | 根据词项命中及上下文扩展选择材料，容易带入长篇背景。 |
| **证据选材** | 收紧上下文关联，以明确标记的原文片段交付，按信息覆盖和增量价值选材，预算只作上限。 |
| **精简实现** | 保留证据选材，移除向量召回和 LLM 重排的可选代码分支。 |
| **精简实现＋BM25** | 启用文档内 BM25 段落检索，并修复评测配置加载，使配置实际生效。 |

“证据选材”和“精简实现”两组运行时都未启用向量召回或 LLM 重排，因此两组费用差异不能归因为关闭模型重排。最近两组的有效配置只有阅读模式不同，均使用 Kimi。此前误以为启用 BM25、实际仍使用默认阅读模式的额外运行已排除。

## 实测结果

助手逐段审读四组实际交付的 181 个非空片段，程序计算指标，没有调用付费 Judge。新增材料使共同正例池由 17 组扩为 23 组；以下 Recall、F1 和 AP 均使用更新后的共同池。每种方案目前各记录一次运行。

| 指标 | 基础选材 | 证据选材 | 精简实现 | 精简实现＋BM25 |
|---|---:|---:|---:|---:|
| Precision | 8.1% | 100% | 81.3% | **100%** |
| Recall（共同池） | 47.8% | 56.5% | 56.5% | **60.9%** |
| F1 | 13.8% | 72.2% | 66.7% | **75.7%** |
| P@10 | 0% | 100% | 80% | **100%** |
| nDCG@10 | 0.046 | 1.000 | 0.882 | **1.000** |
| AP | 0.025 | 0.565 | 0.477 | **0.609** |
| 有效原文字符占比 | 12.1% | 68.2% | **96.0%** | 86.4% |
| 固定事实覆盖 | 15/20 | 17/20 | **19/20** | 17/20 |
| 同源重复片段率 | 0% | 13.3% | 0% | **0%** |
| 模型请求数 | 9 | 28 | 19 | **15** |
| 搜索 API 请求数 | 3 | 8 | 8 | **8** |
| 估算模型费用 | ¥0.85 | ¥3.86 | ¥2.47 | **¥2.13** |
| 执行时间 | 4分13秒 | 14分21秒 | 14分30秒 | **约9分23秒** |

严格相关片段须包含直接事件或人物行为证据；仅提供日期、标题、归因的片段作为上下文。相同原文的复刻合并后计算 Precision、Recall、F1；Recall 的分母是共同池中的 23 组原文。P@10、nDCG 和 AP 按最终交付顺序计算，衡量材料的阅读次序，不代表搜索服务或 BM25 的内部排名。段内无关内容通过有效原文字符占比另行计算。

固定事实覆盖使用同一份 20 项清单。计划交付与已完成交付分别判断；精确股数的完成原句与约数表述也分开。相关段落变多不必然意味着事实更齐全，多个相关的排序指标也不能当作独立收益相加。

费用按非缓存输入 13 元、缓存输入 1.3 元、输出 68 元/百万 token 估算，仅含搜索流程的模型费用。BM25 组的 15 次请求中有一次 HTTP 403，随后恢复完成，14 次正常响应返回了用量。执行时间累计故障前后两段，排除了约 5 分 31 秒的恢复等待；最后一次进程单独记录的约 5 分 45 秒不代表整轮耗时。

## BM25 的收益与漏项

BM25 组实际执行了 9 次段落检索。相比精简实现，本轮模型费用下降 13.5%，执行时间缩短约 35.3%；搜索 API 请求仍为 8 次，正常读源调用由 13 次减少为 9 次。新增的 CNBC 原始访谈交付了巴菲特亲自决定投资、对价格和条款的判断，以及政府行动这一条件。

固定事实覆盖由 19/20 变为 17/20。缺失项包括高盛接洽经过、高管卖股约束，以及“实际收到 13,062,594 股”的精确原句；后续财报仍明确确认实际交付了约 1,310 万股。

逐项检查发现，接洽与高管卖股约束所在网页已经进入候选池且正文已缓存，但 Agent 没有读取；精确收股句所在的伯克希尔年报未进入本轮候选池。对相关文档使用上一轮已有查询做离线重放，BM25 能返回三处关键原文，没有额外模型调用。

因此，现有记录更支持搜索和选源路径差异，未发现 BM25 直接漏排这些原文。BM25 改变阅读上下文也可能间接影响后续选择，单次运行尚不能分离这种影响与随机波动。当前决定是保留 BM25、默认开启，以此作为后续基线，不因单轮内容增减反复回滚。后续重复运行优先观察事实覆盖、费用和耗时的均值与波动。

## 运行与核对

评测入口默认读取[搜索配置](../../configs/search.yml)，同时保留评测的 Kimi 模型和生成参数。BM25 本身在本地计算，不需要模型权重，也不增加模型 API 调用。

```bash
python -m finmy.search.eval --task examples/search_eval/buffett_goldman.json
```

在保存的 `output.json` 中检查 `search_config.retrieval.mode`，在运行的 `trace.jsonl` 中检查 `passage_retrieval` 事件及其 `mode: bm25`。只修改配置文件而未被入口加载，不能算作启用 BM25 的对照组。

相同命令会继续或复用已有任务；重复实验需加 `--fresh`。对照阅读模式可用 `--config` 传入仅含 `retrieval: {mode: topic}` 的配置，保持评测模型不变。评测方法见[搜索评测](../workflows/search-eval.md)，固定来源的离线重放见[段落检索与证据选择](../workflows/search-retrieval-selection.md)。
