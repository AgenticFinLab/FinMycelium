截至 2026-11-26，检索采用任务范围复核版，以精简＋BM25 作为固定对照。工作台新任务默认使用 Ark DeepSeek V4.1 Flash。11 月 24 日的 Kimi 对照使用 Ark，11 月 25 日和 26 日追加的两轮使用 DeepSeek 官方 API。各轮的服务估价和统一单价折算在相应表格中标明。[任务范围复核结果](#latest-20261126) · [仓库搜索配置](../../configs/search.yml)

11 月 24 日的实验围绕巴菲特参与高盛危机投资，核对交易条款、人物决策、赎回及权证结算。该轮在精简＋BM25 的基础上修复了正文缓存与交付，并以修复前的版本作对照。

## 11 月 24 日的功能设置

| 改动 | 当前行为 |
|---|---|
| BM25 段落检索 | 仓库配置默认启用；在已保存文档内找段落，本地计算，无向量模型和 LLM 重排。 |
| 百度/Bocha 正文缓存 | 对缺少正文的结果获取原始 URL 并缓存，供 `read_source` 使用；搜索摘要仍作线索。 |
| 撤掉搜索正文预览 | 搜索反馈保留来源和发现线索；已读原文在模型上下文中的预览继续保留。 |
| context 新事实保留 | `context` 携带尚未覆盖的 `fact_ids` 时可入选；纯背景和已覆盖事实不增加价值，重复检查继续生效。 |
| 读后漏标提示与标记状态 | 已读原文显示 `marked`、`partial`、`unmarked`；提醒模型补标有用事实，沿用现有动作和上下文预算。 |
| 原句边界对齐 | 新标记可在同版本、同原文块、已经读过的范围内补齐完整句；表格不做普通句界扩展，历史交付坐标保持原样。 |

原有 finish 事实检查继续保留。交付修复没有新增模型阶段；90,000 字符仍是交付上限，允许留下未用预算。具体规则见[段落检索与证据选择](../workflows/search-retrieval-selection.md)。

## 保留依据与运行波动

当前两轮平均 F1 为 60.2%，精简＋BM25 为 62.2%；完整事实平均 17.5 项对 17 项。平均模型费约 ¥2.43 对 ¥2.13，增加 13.8%。检索表现接近，已有交付修复是保留当前版本的主要理由。

- **context 修复有直接收益。** 固定第1次运行的模型决策，关闭该规则会丢失“长期关系促成接洽”，完整事实 18→17；第2次会丢失 2009 年持仓原句，17→16。其余交付原文相同。
- **句界修复处理了真实截句。** 对保存的模型决策做固定回放，补齐了缺失的 85 个原文字符。当前第1次补入了 263 个公司简介字符，因为原始终点已落进简介；第2次原标记已完整，没有触发坐标扩展。
- **同版本的搜索路径明显不同。** 第1次没有召回 CNBC；第2次在交易主线完成后专门搜索人物参与证据，并继续读取谈判回答，恢复了本人提出条款、对方接受及投资时机的原话。两次都完整交付了实际收到 13,062,594 股的原句。
- **覆盖仍有替换。** 第1次覆盖接洽背景和高管售股限制；第2次对应回顾页有缓存却未读。两轮完整事实并集为 19 项，政府行动的明确投资前提仍缺失。第2次持仓表带入较多其他公司行，有效原文占比降至 83.0%。

第2次总耗时升至 12分46秒，其中三次百度请求各约 121 秒，合计约 6 分钟；模型请求累计耗时从第1次的 214 秒升至 261 秒。两轮均未读取或交付百度/Bocha 提供的来源，正文缓存通路的保留与实际选源收益分别记录。

## 运行与核对

当前评测入口从仓库配置读取搜索模型，默认使用 Ark DeepSeek V4.1 Flash。复现上表的 Kimi 轮次时，使用 `--config` 指定当时的 `ark/kimi-k3-1-pro-261024`、`low` 和 8,192 token。后文两轮官方 DeepSeek 实验的模型、服务与成本按各自记录保留。[搜索配置](../../configs/search.yml)

使用当前默认配置独立运行：

```bash
python -m finmy.search.eval \
  --task examples/search_eval/buffett_goldman.json \
  --eval_mode manual \
  --fresh
```

在 `output.json` 中核对任务、实际搜索配置与代码标识；在 `trace.jsonl` 中检查 `passage_retrieval` 的 `mode: bm25`。按功能名称给各版本命名，同代码的复跑分别列出，并同时报告均值。

相同命令不加 `--fresh` 会继续或复用已有任务；每次加 `--fresh` 都会新建独立运行。评测与检查点说明见[搜索评测](../workflows/search-eval.md)。对照阅读模式可用 `--config` 传入仅含 `retrieval: {mode: topic}` 的配置，保持评测模型不变。
