# 事件主表建设

建设有来源支撑、范围明确的事件目录。默认目标为**总计10,000条有效事件**，用户指定目标优先；默认约200条合格入选为批次目标，不能降低标准凑数。

先读[操作流程](references/runbook.md)，研究及落账时遵循[审计约定](references/research-and-audit.md)。复用skill的预检、流程工具与回归测试，不依赖本机历史批次脚本。

## 起点与边界

定位实际FinMycelium和EPG-dataset仓库，读取适用AGENTS.md、当前主表规范/模板及已有研究计划、来源、决策、检查点。当前CSV为数据权威；README只作导航。初建在独立暂存区从公开来源研究，续跑先核对现有基线和未决项，复查不能直接继承历史complete。

旧data/events两表和manifest已退役，不恢复或使用；旧draft不读取、不修改，也不作为证据。默认不启动搜索服务、Builder、Web导入或工作台数据库写入，除非用户另行要求。

## 核心流程

1. **冻结基线**：保留稳定ID、历史去向和实际执行信息，独立初建不覆盖现行目录。
2. **研究并规范化**：使用执行agent的公开网页搜索、正文及文档阅读能力，逐候选确认事项、主体、日期含义及范围。摘要、模型记忆和链接存在不能代替阅读；未知日期留空，关键证据不足者暂缓。
3. **全局去重**：对全表现有事件和本批候选召回，比较具体事项与过程连续性。标题相似不自动合并，编号或日期不同不自动判独立；不能把新闻、年度或程序节点拆成重复事件。保留的包含/重叠事项说明边界与关系。
4. **补足覆盖**：统计领域、地域、年代、机制及来源语言，优先研究缺口，不局限金融。
5. **全表终检**：核对全部有效行的来源、身份/日期/范围、规范、关系及重复候选。可复用定位充分的未变证据，准确保留阅读限制；修订后刷新受影响行和召回。
6. **验收交付**：暂存验证通过后发布主表、来源及审计，更新研究计划、质量报告和检查点；分别验证Web上传与目录直读，生成派生输入。

## 完成条件

目标有效数达到；每条有充分来源及逐行结论；历史去向齐全；规范、引用、变更重放及本轮候选裁决完成，无关键未决；覆盖偏差和接口限制已说明。工具检查只验证数据和记录一致性，不认证真实性。网络或证据不足时保存可恢复进度，不虚报完成。

正式成果放event-epg，缓存放output。新事件planned、owner和成果路径空；保留已有执行信息，主表核查不等于图accepted。交付实际计数、变更、报告、检查结果和限制。研究方法可以复现，公开来源变化下不承诺结果逐字相同。
