# 事件集主表格式

## 编号与历史基线

历史 3,000 项均已确认入选；补研进度和字段完整性单独检查。新增候选按[事件入选标准](event-selection.md)判定后登记。

完整主表按数值顺序排列，从 `event1` 连续到 `eventN`。前 3,000 个编号逐一绑定 `EPG-dataset/data/events/events.csv` 的历史事件。取历史 ID 的数字部分，去掉前导零，例如 `H2EPR-0001 → event1`、`H2EPR-0002 → event2`、`H2EPR-3000 → event3000`。按 ID 映射，历史 CSV 排序变化也能复现同一对应关系。

新增事件从 `event3001` 起顺延。更新标题、范围、分类或查重结果均保留原行与原编号。即使前 3,000 项中发现重复，也要保留两条登记并填写重复标记；最终独立事件数可以与主表行数不同。分批研究可只交付选中的编号。

一行表示一条稳定的事件登记记录。文件使用 UTF-8（可带 BOM）、英文逗号、模板表头顺序。字段带逗号、双引号或换行时由标准 CSV 写入器加双引号并转义。编号和日期按文本保存。标量未知留空；多值单元格写 JSON 数组，空集用 `[]` 或留空。例如关键词的单元格内容为 `["ACME, Inc.", "permit"]`，在原始 CSV 中写成 `"[""ACME, Inc."", ""permit""]"`。

## 主表录入与事实核验

完整主表和分批交付使用相同的 18 列。**每行必填 9 列：event_id、event_name_zh、event_name_en、description、domain、category、scope_include、keywords、source_hints。** 先用原文确认核心事项，再据此确定分类、划定研究范围并提取检索词。尚缺必填信息的历史事件保留编号，在工作稿中补研，齐备后再交付该行。完整交付仍须覆盖全部历史编号。

**语言。** 只有 event_name_zh 可以使用中文；其他字段中的叙述、分类、专名、数组元素、来源说明及关系对象的 note 一律用英文。采用已有英文名称或通行的罗马字拼写。非英文文献照样可用：在 source_hints 写英文释义，必要时标明 “title translated”，保留可访问的原始 URL 或档案编号。ID、日期、URL、路径、枚举和布尔值使用各自的机器格式。项目名的缩写和专名中的重音字母可保留。

**证据。** 先打开原始材料，核对它指向的主体、事件、时间和动作，再写简介。法院文书区分起诉与判决，公告区分宣布与完成。历史摘要、搜索结果摘录和其他行只提供线索。来源相互冲突时核对文书版本、日期口径及主体；仍有分歧就缩小表述范围或用英文标注归属，选填值可留空。所有已填事实都应能追溯到已读材料。研究范围属于任务选择，应明确写成拟调查的范围。交付前逐行核对两种名称是否同指一事、简介中每个实质性断言能否从所列材料定位。禁止编造名称、引文、日期、参与方、来源和图路径。

## 18 个字段的填写规则

**按事件写作。** 模板规定列名、顺序和类型。名称与简介应让不了解此案的读者能辨认具体事项。选取原文真正支持且能区分本案的行动、决定、对象或变化，按证据决定写几句。一个关键决定足以说明问题时可以只写一句。历史行已获选的是事件身份；旧简介中提到的治理失灵、损失、调查、整改等仍须逐项核实。

例如，笼统写 “The crisis led to investigations and losses” 会给 FTX 行引入两个待证结果。示例从 SEC 诉状第 79–81 段提取暂停提款和寻求资金的经过，用破产申请书首页核对债务人、案号、法院及申请日期。研究窗口止于申请，清偿结果属于后续窗口。工程事故或外交决定可直接从各自原文选择最能说明本案的事实。

**逐行回读。** 遮住事件名后，如果同一类别的许多记录仍可原样套用这段简介，回到原文补上有依据的区别，或删去空泛断言。检查 scope_include 是否真能指导下一位研究者决定哪些材料属于本行；scope_exclude 只写实际易混的相邻事项。两种事件名对程序状态和责任归属应与简介一致。金额、人数、比例要核对单位、时间和口径；后来的更正按版本处理。来源只给出先后顺序时，保留先后关系，另将原因作为待查问题。同类事件确实共享准确表述时可保留，靠变换同义词无法改善事实质量。

涉及不同时点的数值时，写明截至何时、对应哪个对象，以及是估计、申请、裁定还是实际执行。英文技术叙述可使用原材料中的科学符号和单位（如 β、μg）。来源索引中的题名可以照录原文，主表中的英文释义与原 URL 或正式档号一起保留。

来源写“大约”“不晚于”或只给时间区间时，在英文叙述中保留限定。填写活动日期只取材料能够确定的精度；例如只能确定在某年 11 月内，就填到月份，跨月且没有可确认的月份时再看年份是否确定。若另一份原始记录能确定具体日期，在该行指出依据。写“首次”“唯一”“全部”或“从未发生”前，须有覆盖相应对象和时段的材料，检索未命中时仍作为待查问题。

source_hints 中每份已引文献都要有带 `SRC-` 编号的英文说明，写明原文位置及它支持的事实。索引里有 URL 的文献，把同一 URL 另列为数组一项；几份材料共用一个 URL 时只列一次，各版本仍分别说明。只有正式文号的文献，将文号写入带 ID 的说明，或按来源索引的 publication_info 单列文号。原文档号含非拉丁文字时，在索引保留原貌，主表用同一个来源 ID、英文发文机构和可辨认的编号部分定位。额外搜索方向记在研究计划的待查项。

FinMycelium 从单独的 URL 数组项提取检索起始链接。主表和来源索引均使用小写 `https://` 或 `http://`，保留原路径、查询参数和片段的大小写。

对可以通过检索确认的事件事实，默认以填全为目标。对照同一条记录的名称、简介、研究范围及所引原文检查每个字段。材料已经点名的参与方、明确的管辖区和位于研究窗口边界的活动日期，都应同步填入相应列。初读材料缺少某项时，用该项对应的主体、地名、行动或案号定向查找。缺证、来源冲突且无法消解、或该事实对本事件不适用时，才将该项作为选填留空。

部分信息能确认时，填写已确认部分。例如，若申请是本行的开始节点且只能确认年份，就在 coverage_start 填 `2022`。只查明一个当事方，就在 participants 写入该主体。事件的两个日期边界、其他当事方及事件别名分别核实。

下表覆盖三种填写要求。9 个必填字段须在交付时齐全。5 个“核实后必填”字段须定向检索，证实多少填多少。4 个“条件必填”字段只在各自条件成立时填写。缺失标量留空，空数组写 `[]` 或留空；必填数组至少有一个有效项。`is_duplicate` 未标重复时必须是空单元格。各字段均禁止用 `TBD`、`N/A`、`unknown` 等占位符充数。

| 字段 | 要求 | 内容与格式 |
| --- | --- | --- |
| `event_id` | 必填 | 唯一、稳定的小写 event 加正整数，遵循上文历史映射。如 `event2`。 |
| `event_name_zh` | 必填 | 中文显示名，可保留 FTX 一类通行缩写。优先用已有中文名；没有公认译名时，按已核实的主体与事项写准确的描述性中文名称。 |
| `event_name_en` | 必填 | 英文显示名，写清对象和具体事项。没有通行英文名时，可据原文拟描述性名称。遇到同名或反复发生的事项，用已核实的年份、地点、对象或程序节点区分。中英文名覆盖同一事项和阶段。 |
| `aliases` | 核实后必填 | 英文或罗马字字符串数组。收录已读材料确实用来指称**本事件**的简称、旧称或拼写变体。主名已在名称列；公司简称、案号或产品名若只用于定位事件，可放 keywords。 |
| `description` | 必填 | 用英文写明已发生的行动或变化及涉及对象，结果已知时再写结果。结果尚未确定时可写已核实的最近节点。将指控或当事方说法归于具体来源，每项关键事实应有定位。 |
| `domain` | 必填 | 单个英文领域标签，如 `Finance`。按实际研究对象确定主领域；与 category 的组合及新标签的适用边界见[领域与类别规划](domain-category-plan.md)。 |
| `category` | 必填 | 单个英文事项类别，如 `Bankruptcy`。在主领域下按所研究的具体过程归类，如申请破产保护。分类是据事实作出的整理判断，来源无需使用相同标签；避免仅凭主体所属行业、旧标签或未经证实的指控定类。 |
| `country_region` | 核实后必填 | 英文国家或地区名数组。逐项填研究窗口内行动的发生地或直接管辖区。跨境事项可有多项，同一地点采用一致英文名称。城市、法院或设施可在简介中具体说明。总部、报道发布地或仅推测受到波及的市场不足以确定此列。 |
| `participants` | 核实后必填 | 英文或通行罗马字名称数组，一项一个有原文依据的当事人、机构或具名群体。纳入在研究窗口内采取行动或被具体决定直接针对的主体。媒体、作者或监管机构仅因署名、报道或事后评论不足以入列。角色及其行动可写入简介，数组只放名称。 |
| `coverage_start` | 核实后必填 | 本行纳入的首个活动边界，按原文精度填 `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`。研究窗口从申请开始就用申请节点；更早的背景、后来的报道或查阅日期都不能代替。 |
| `coverage_end` | 核实后必填 | 本行纳入的终止节点，格式同上。整个窗口只研究一个已核实的单日决定时，两端可同日。两端精度可不同。事项仍在进行时，若本行止于已证实的某次行动，填该行动日期；若截止节点尚未发生或日期无据，留空。 |
| `scope_include` | 必填 | 用英文说明本行要重建的对象、行动及边界。边界可以是可辨认的程序节点；具体日期未知也可界定。开放中的事项说明当前追踪到什么进展，把尚待确认的结果写成研究问题。 |
| `scope_exclude` | 条件必填 | 有容易混入的相邻事项或阶段时，用英文点明排除哪一部分，例如申请破产保护之后的债权分配。没有具体混淆对象就留空。未查清但仍属于本行的问题留在研究计划中继续核查。 |
| `keywords` | 必填 | 非空字符串数组，从已核实的事件名或已读材料提取可检索的英文短语、专名、案号等。每项一个有助于定位本事件的词或编号。 |
| `source_hints` | 必填 | 非空字符串数组。填写已读材料的 URL（单独一项）或可检索的正式文号，再用英文写明材料、页码、段落或小节以及支持的事实。定位说明引用同目录 sources.csv 的 source_id，多份文献分别对应。网页无页码时使用小节名或段落开头。 |
| `related_events` | 条件必填 | 已确认本行为重复行时须指向保留记录；已核实且有助于界定本行范围的其他关联也应登记，未建立关联时可留空。JSON 对象数组，每项恰含 `event_id`、`relation_type`、`note`。关系取 `overlap`、`contains`、`part_of`、`possible_duplicate`、`related`。用英文说明两行之间的具体联系；每个目标只出现一次，禁止自指。 |
| `epg_path` | 条件必填 | 最终图生成且确定采用后，按普通事件的收录约定填写 `events/<本行event_id>/epg/epg.json`，此前留空。核对图对应的构建任务、事件和采用版本，防止将另一事件的图复制到正确路径后误登记。 |
| `is_duplicate` | 条件必填 | 仅确认重复行填写小写 `true`。独立事件、重复组的代表行及尚待核实的行均保留空单元格。查重进度按批记录在新版 research-plan.md，配对依据记入同目录 ISSUES.md。为 true 时用 related_events 中的 `related` 指向保留行，并用英文写明判重依据。 |

**分类和检索词。** 每行只填一组 `domain`、`category`。每列一个英文标签，禁止用数组、分号、竖线或换行拼接多个标签。优先复用计划中的准确拼写，保留标签本身的标点，如 `Corporate Governance, IPOs & M&A`。跨领域时按本行追踪的核心过程选主类，其他有助于查找的概念可以写入 keywords。确需新标签时按分类规划说明边界，再按同一拼写使用。

**关系方向。** 从本行读向目标 ID。`contains` 表示本行范围包含目标事项，`part_of` 表示本行是目标事项的一部分。若双方分别研究独立过程且有交集，用 `overlap`，在 note 中说明交集及各自边界。其他有据的具体联系可用 `related`。`possible_duplicate` 仅供工作稿记录尚待查明的同一性，此时重复标记留空；证实重复后，由重复行用 `related` 指向代表行并标 `true`。为同一对事件从两端都登记关系时，注意包含方向相反。每条 note 都用英文说明实际联系。

## 历史字段怎样进入主表

将旧 title 按语言归入名称工作稿，description、domain 和 category 作为检索起点。旧 keywords 按历史分隔符（空格、竖线、空格）拆分、去重，用于初查。交付时只选与本行窗口有关、且由已核实名称或已读原文支持的词，尤其回查旧表里的罪名、责任归属与损失描述。历史记录的 scope_note 全空，三类审核状态均为 not_reviewed。逐条阅读后再填写范围与来源；初始化时 epg_path 和 is_duplicate 均留空。

[FTX 示例](../assets/events.example.csv) 对应历史 H2EPR-0002。保留 event2，同时把研究窗口界定为暂停提款至申请破产保护。示例的 source_hints 给出来源 URL 和具体段落。

## FinMycelium 接口

主表写入 `EPG-dataset/event-epg/events.csv`，DatasetCatalog 从数据集根目录直接读取。向 Workbench 本机记录上传 CSV 时，将 epg_path 和 is_duplicate 映射为“不导入”，其余 16 列按同名字段读取。单次上传 1–5,000 行且不超过 20 MiB，完整主表可独立于上传分片维护。主表负责保存图路径；现有图收录流程另有状态及审核字段要求。

填写 epg_path 前，用 Workbench 普通事件图读取器确认 JSON 可解析、阶段和情节结构有效，再按构建任务所绑定的主表事件、实际采用的图版本核对归属。图内标识属于构建产物，保留其原值。空文件、其他类型的 JSON 或尚待采用的草稿应使该字段继续留空。
