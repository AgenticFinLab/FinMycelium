# 建库顺序与阶段验收

## 文件职责

历史事件输入为 `EPG-dataset/data/events/events.csv`。从这一份文件取得基线身份和检索线索，重新查证公开原文。旧 `data/events/ISSUES.md` 与重建前的整个 `event-epg/` 均属退役版本，排除在读取、合并、查重和续做基线之外。

新版输出根固定为 `EPG-dataset/event-epg/`。借鉴 `person-epg/<person>/` 的主表、研究计划、来源索引和目录导航，采用普通事件读取器约定的 ID 目录：

```text
event-epg/
  README.md
  events.csv
  research-plan.md
  sources.csv
  ISSUES.md
  events/<event_id>/
    search/              # 实际采用的检索交接材料
    epg/epg.json         # 实际生成并采用的事件图
```

首次执行时从空目录建立本轮工作集，创建上述五份根文件。若最终路径仍被旧目录占用，在独立的干净工作目录准备新版，再将完整新版发布到目标路径，避免新旧文件混存。续做时只接续能与本轮研究计划、批次和来源记录对上的新版。事件的 search/ 与 epg/ 随实际产物创建。

| 新版文件 | 如何维护 |
| --- | --- |
| `events.csv` | 用 [18 列主表模板](../assets/events.input.template.csv) 初始化，按稳定 event_id 更新。epg_path 是相对于 event-epg/ 的实际图路径。 |
| `research-plan.md` | 用[研究计划模板](../assets/research-plan.template.md)说明基线、研究问题、两阶段目标、本批范围和进度、查重覆盖、未决事项及交接。分批保存实际完成的 ID 或区间；单条事件事实由主表维护。 |
| `sources.csv` | 使用与 person-epg 来源索引一致的[六列表头](../assets/sources.template.csv)。本数据集直接维护这份全局索引，计划通过 source_id 引用它。每份实际读过的文档分配稳定 ID（例如 SRC-0001），同一文档跨事件复用 ID。title 和 publication_info 登记标题与可核实的发布信息；url 写真实链接，只有正式档号时在 publication_info 记档号；reading_note 记阅读位置；support_note 按 event_id 写明所支持的事实及限制。 |
| `ISSUES.md` | 从[问题记录模板](../assets/issues.template.md)重新建档。登记本轮的配对裁决、来源定位、单条身份问题及更正。 |
| `README.md` | 链接以上四份文件，交代两阶段建库顺序、编号规则和实际事件产物的位置。进度指向研究计划。 |

在每行 source_hints 的英文定位说明中引用新版 source_id，保留独立的原文 URL 项或可定位文号。每批同时核对：引用的 source_id 唯一且能在索引中找到、support_note 所指 event_id 存在、已读材料确能支持该行的表述。普通事件目录按事件 ID 定位；领域与类别保留在主表。

来源 ID 采用 `SRC-` 加数字。同一文档可支持多条事件，support_note 写清对应每个 ID 的具体事实。多家转载同一份公告时追溯到原公告；涉及争议、责任或金额口径时，查找有独立依据的材料，或将结论收窄到能够归属的陈述。只有摘要可读时按实际阅读范围登记；原文无法访问则寻找可读版本，只有检索线索的文献留在研究计划待查项。

在同一个 CSV 单元格内，support_note 每行以 `eventN: ` 开头，随后用自己的话说明这份材料对该事件能证实什么、有哪些限制。多行单元格按 CSV 规则加双引号。正文里提到另一个 ID 作比较，不构成对该 ID 的证据归属。来源涉及多行时，逐行区分各自的行动、时间或程序状态。

**来源修订与范围变更。** 页面可能在同一 URL 发布更正。依据发生变化时，用 publication_info 标明实际看到的版本、发布日期或查阅日期。更正文件或内容有实质差异的版本单列来源 ID，保留旧版本的真实阅读记录。沿旧 source_id 找出受影响的行，逐项核对简介、名称、日期、参与方及查重理由。缩小研究窗口时，删去已经超出范围的断言和对应引用，并更新 support_note；仅用于解释历史裁决的来源可以保留在 ISSUES.md 的上下文中。若变更影响已经采用的图，复查其适用范围，确认可继续采用后再登记为当前成果。

**中断与续做。** 发现主表、来源索引、ISSUES.md 和研究计划记录的批次不同步时，用上一个完整批次和本批实际写入的 ID 对账。保留已核实的修改，补齐缺失的引用或裁决，重新检查受影响行，然后推进进度。初始化的空字段、可访问的 URL 或“已完成”字样均不能作为阅读证据。

首次登记时在 research-plan.md 记下实际使用的历史输入路径和可回查的文件版本（Git 对象或文件 SHA-256）。续做若版本变化，用原始 `H2EPR-` 编号比较题名、分类和检索线索；仅排序或换行变化可继续，有身份或内容变化则列出受影响的 ID 再复核。版本记录用于找回原输入，来源事实仍逐条查证。

## 阶段一：登记并核实历史 3,000 项

1. **初始化身份。** 核对原始 ID 集恰为 `H2EPR-0001` 至 `H2EPR-3000`，每个一次。按数字部分建立 `event1` 至 `event3000`，按数值顺序写入主表工作稿。以原 ID 连接输入，英文标题作为起始题名。旧简介、分类、关键词可用于搜索，核实后按[主表规范](input-format.md)填写。未查重的行保持 `is_duplicate` 为空。初始化工作稿与阶段验收是两个不同的进度节点。
2. **逐条搜索并读原文。** 每个 ID 都用事件名称、主体、异名或正式编号查找资料。打开能确认具体事项的原文，把 URL 或文号、页码或段落以及支持的事实写进本行 `source_hints`。核对两种名称、简介、研究窗口和关键行动，区分活动日期与发布日期。核心主张与来源冲突时，更正有依据的表述，或在 `ISSUES.md` 记录 ID、已读材料、冲突点与下一步。保持同一事件身份。在 research-plan.md 按批保存已核 ID 和待核 ID，续做优先处理缺口。
3. **跨全表查重。** 每条记录同时与其余历史记录比较。先用双语名称、异名、主体和正式编号寻找可能配对，再扩大到时间、地点、对象和关键行动相近的事件；覆盖跨类别、跨批次及不同语言的记录。名称相似度只用于发现候选。对每个可疑配对，分别从原文核对两个 ID 的身份及纳入范围。两行使用同一来源也可能描述不同事项。
4. **同步主表与问题记录。** 确认同一事项且核心研究范围实质相同时，保留两个历史行及编号，选一条作为代表行。优先保留范围准确、证据定位清楚的行；条件相同选数字较小的 ID。代表行的 `is_duplicate` 留空，其余重复行标 `true`，并在 `related_events` 通过 `related` 和英文理由直接指向代表行。若同组超过两条，每条重复行都要有证据支持它与代表行的对应。范围部分重叠但可以独立研究时保留两条，注明重叠及各自边界。身份仍存疑时保留问题和未决状态。

### ISSUES.md 的本轮记录

同一事件可能同时关联多个事项。确认重复时，在裁决记录中明确写出“重复行 ID → 代表行 ID”，与主表中这条直接关系的英文理由核对。代表行留空且经本轮查重；若原代表行随后并入另一组，同步复查组内每个成员与新代表的对应关系。批内允许引用批外 ID，交付全表时须能解析全部目标。

在模板的 `Pair decisions` 表中，每对已登记 ID 只维护一条当前裁决，即使另一个批次以相反次序发现这两个 ID。第二列填写 `eventA → eventB`（A 是重复行，B 是代表行）、`overlap`（边界有交集、可独立研究）、`distinct`（已排除重复）或 `pending`（尚待核实）。其他列写本案名称、比较点、理由、来源定位及实际核查日期。结案时所引来源合计覆盖两方。没有可疑配对时保留空表，在研究计划中登记实际查重覆盖范围。

更正时更新当前行，把旧结论和更正依据保留在理由列或 `Other issues` 中。单条身份冲突也记在 `Other issues`，标明是否影响阶段验收。验收时脚本检查配对表，执行者另行回读单条未决事项。单个选填日期仍缺证可以留空；核心身份未定必须继续核查。

“重复的具体内容”要说明哪些主体、对象、行动和期间指向同一事项；“依据”要让读者能够沿链接或文号定位原文，看出它如何把两个题名对应到一起。只有范围重叠、已排除重复、尚待核实的配对分别写明结论。记录本轮真实查阅日期及新版来源索引中的定位。

确认重复的依据列须引用本轮 `SRC-` 编号，并写明原文位置和能连接两个事项的事实。两份材料分别证明两方身份时，分别交代匹配点。核查日期用实际完成复核的日历日（`YYYY-MM-DD`）。

所引材料在 sources.csv 的 `support_note` 合起来须覆盖双方 ID。若同一份材料能辨认两个题名，分别说明它对每个 ID 的支持；若各有文书，在裁决中解释两份文书的案号、当事方、行动或范围如何对应。仅因共用来源或编号相近不能裁定重复。

撤销误判时，先核对该行与组内其他成员。如果没有其他已证实的代表行，清空原重复标记，删除仅因误判而建立的关系；确有独立关系时按原文更新其类型和理由。把 ISSUES.md 的当前结论改成复核结果，保留原判断、更正原因与新依据。同步复核曾指向该行的记录，更新研究计划中受影响的 ID、未决事项和独立事件数。核查中可登记 `possible_duplicate`；两次阶段验收前，每条此类关系都须落实裁决并更新主表。

### 可以开始新增的条件

历史编号按原始 CSV 的 `H2EPR-NNNN` 回查。对改过范围或名称的行，对照双方主体、具体事项以及本轮原文；若原始输入与新题名表面上指向不同事项，在 ISSUES.md 写明采用依据。相邻行互换内容也可能保持编号连续，不能用行数或新旧名称相等代替身份核对。

批次交付前按[逐行回读规则](input-format.md)检查内容。运行校验时带上本批实际使用的来源索引及 `--review-prose`；对提示的相同表述检查是否混入其他事件的事实，另对同类别只替换主体或略改措辞的简介做并排阅读。措辞相似只产生复查提示；是否重复事件仍按身份、范围及证据裁决。

- 主表恰有 3,000 个历史 ID；逐条对应原始事项，每条完成本轮检索，有可复查的来源和已核实的必填内容。按规范允许留空的选填事实可保留缺口。
- 全表查重覆盖所有 ID，影响身份或重复结论的待定配对已解决。在 `research-plan.md` 按批记录已完成查重的 ID（连续编号可写范围），在新版 `ISSUES.md` 维护待核配对，验收时按这两份记录核对覆盖情况。每个 `true` 直接指向一个存在且标记留空的代表行，并与本轮证据逐一对应。
- 对整张主表运行 `check_input.py --stage baseline <主表路径>`，核对 3,000 条及交付文件。再按本轮实际研究和查重记录核对覆盖的 ID 集、尚待核对的 ID 集和 ISSUES.md 中未解决的问题。区间重叠按 ID 去重计数；只初始化了 3,000 行或通过格式检查时，继续保留原进度。在 research-plan.md 记下核对日期、结论及未决问题。独立事件数按 `3000 − 重复行数` 计算；配对数单独统计。核心身份、必填事实或查重结论仍待核时，继续阶段一。

按研究计划模板分别维护 `Research completed` 和 `Duplicate review coverage`。前者记录已经逐条读原文、核实主表事实的 ID；后者记录已经与全库候选比对且影响身份的疑点均已解决的 ID。候选主题、计划工作量和开放问题在相邻列自由描述。阶段检查分别核对两列的 ID 并集；复查尚未完成时，同一个 ID 在相应列的所有批次中都应撤下。

## 阶段二：扩充至 10,000 条

阶段一完成后，按[领域和类别计划](domain-category-plan.md)寻找候选。若检索中发现材料具体补充或更正了某个已有事件，核对身份及窗口后更新该行，即使这条线索本身不足以单独立项。对拟新增的候选，按[入选标准](event-selection.md)核实该事项自身的实际影响和可重建的过程；证据不足时按具体线索决定暂存或跳过。**分配新编号前**，与全部历史行（含重复行和别名）、已收录新增行及同批候选查重。范围独立且查重完成后才取得下一个编号，其 `is_duplicate` 留空。每批落表前按最新主表再核一次。

未编号候选用题名、可定位的行动或文号记录在研究计划的候选范围或工作稿中。若与既有行重复，仅将支持该行的新材料登记到相应 ID。多批可同时检索，合入新版主表时逐批进行；以刚合入的最新结果重查候选及来源，复用已有文献编号，再统一分配本批新事件和新来源编号。若待合入的工作稿曾暂编 ID，同时更新其中的来源说明、关系和配对记录后再校验。

在落表前回读候选的简介、范围和来源定位。剔除尚未核实的因果或责任说法后，应能指出已发生的实质变化，沿原文重建行动或状态的演变，并与容易混淆的已有事项划清边界。身份仍有歧义时，先在候选工作稿记下待比对的 ID 和能区分它们的原文线索。涉及拆分、合并或暂存的疑难案例，在本批研究计划中简记[判定依据](event-selection.md)，便于下一批接续。

新增区间为 `event3001` 至 `event10000`，共 7,000 条。每批只计已通过核验并实际写入主表的事件。合格但本批未选用的候选按[批次取舍规则](event-selection.md)保留线索，与缺证待查的事项分别注明原因。最终分别报告主表登记行数、历史重复行数、查重后的独立事件数，以及各类别相对计划的差额。

续做时以最新主表核对上批 ID 和来源，再从首个未完成事项继续。先在工作区核对本批主表、来源索引、问题记录，再更新研究计划中的已完成范围；中断重跑复用同一事件和来源的 ID。若入表后发现新增区误收重复，保留事实标记并在 ISSUES.md 记录影响；暂停最终验收，先核对受影响的引用与已有成果，避免将已被引用的编号直接改派给其他事项。

最终交付运行 `check_input.py --stage final <主表路径>`。此项检查要求恰有 10,000 条、编号连续和新增区无已标重复行。随后对照批次记录复核全库查重覆盖与未决裁决；空白标记、文件存在、命令成功都不能单独证明已完成事实研究或全库查重。
