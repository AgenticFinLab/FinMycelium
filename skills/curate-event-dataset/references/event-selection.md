# 哪些事件值得单独研究

`EPG-dataset/data/events/events.csv` 中的 3,000 条是用户已确认入选的基线，对应 `event1` 至 `event3000`。保留其身份，逐项核实和补全新版字段。以下标准用于选择新增事件，也用于澄清既有行的研究范围。基线覆盖 6 个领域、26 个类别；这些分类可用于寻找同类案例，数量分布不作为新增配额。

## 新增事件按自身的研究价值判断

FinMycelium 的研究目的是从分散的公开文档中重建具体事件的演进过程，形成可追溯的结构化时间线。对新增候选，先回答：**把已知材料按时间和行动联系起来，能帮助研究者理解什么？** 例如，一项影响服务运行的决定是如何作出的、其间采取了哪些措施、可观察到的结果如何变化。

- **实际影响。** 指出谁或哪个系统受到影响，哪种状态发生了实质变化，以及追踪其演变能回答什么问题。变化可以来自正式决定，也可以表现为流动性枯竭、服务失灵或供给持续受阻。对有固定披露或运行周期的候选，用可比的正常情形判断：材料只是详细描述预定程序，还是记录了足以改变服务、权利义务或后续处置的事实？资料多寡、机构知名度和潜在影响都不能单独决定入选。
- **可重建的过程。** 打开原文，尝试按实际顺序讲清这件事。除确认“何时发生了什么”外，材料还须能解释关键决定怎样形成或执行、相关方怎样响应、影响怎样显现或恢复中的至少一方面，并能把相关行动或变化定位到原文。单份详实的调查报告或裁决书可以满足这个要求。多篇报道若都转述同一句通告，仍只提供那一句通告的信息。

原有 3,000 项提供整体选题尺度：对象具体、变化值得追踪、证据能够支撑过程研究。下方案例仅供理解粒度；无需逐案配对、提交参考 ID 或沿用既有事件类型。查重时检查的是同一现实事项是否已经登记。

## 对象、范围和证据

| 判断 | Codex 应能给出的具体回答 |
| --- | --- |
| **能辨认是哪一件事** | 指出发生了什么，以及能区分这件事的主体、对象、地点、时期、正式决定或编号。例如“2013 年 Nasdaq SIP 故障”可以定位；“交易所技术风险”还需缩小到具体事项。 |
| **能界定独立的研究范围** | 用一句话说明从哪个节点查起、追踪哪些行动、到哪个结果或已知节点为止。发现可能指向同一事项的已有记录时，核对双方对象和范围。新报道或同一公告的译本可补入已有行；相连事项若有各自可独立研究的行动、材料和边界，可以分别登记并标注关联。 |
| **有公开证据可核实** | 打开能定位的原文，指出具体文件、段落或记录支持哪项核心事实，例如事故记录、监管决定、法院文书或研究报告。新闻转述当事方声明时，沿引文回查谁亲历、记录或提出了这项主张。各家都引用同一说法时，仅按其实际来源归属。若争议事实是唯一的入选理由，须补到有独立依据的材料；仍无法核实，按下文暂存或跳过。 |

同一文档覆盖多个主体或事项时，按候选的对象、行动和时段回读相关段落。整场危机的累计损失、全国受影响人数或集团处置规模，只能按原统计范围使用。判断一个地方或子公司的事件能否独立入选，要能定位到它自身的变化及处置；即使没有单独披露金额，有据可查的停运、接管或权利变化也可以说明影响。

例如，[FTX 示例](../assets/events.example.csv)的两份原文支持不同层次的判断。SEC 诉状第 86 段概述 FTX 与多家关联实体申请破产保护；案号 22-11068 的申请书首页列明债务人为 FTX Trading Ltd.。若候选是另一家关联公司的独立处置，还须查清针对该公司的行动及其研究范围。集团名单只提供查找线索。[SEC 诉状](https://www.sec.gov/files/litigation/complaints/2022/comp-pr2022-219.pdf) · [破产申请书首页](https://cdn.decrypt.co/wp-content/uploads/2022/11/ftx-group-chpt-11-filing.pdf)

## 容易判错的边界

| 候选情况 | 判断方法 |
| --- | --- |
| 预测、拟议措施或尚在进行的调查 | 以研究窗口内已发生的行动判断影响。预估损失、计划停产或未经证实的指控，不能当作已发生的后果。正式启动程序、签发停工令或执行预防性关闭，本身可能改变运营或权利义务；若这段过程已具研究价值且有据可查，就以它为题入选，结局可以未知。只有一条立案消息时仍须通过资料充足度判定。 |
| 预案或演练材料比实际处置记录更详细 | 预案能说明应当怎样做，演练记录能说明模拟了什么。重建真实事故时，须用与该次事故对应的材料核实实际执行了哪些步骤。若可证实的是演练引发了一项实质整改，则可以围绕该整改本身评估，模拟损失不计入实际影响。 |
| 同一事件的通报、阶段和后续处置 | 把候选放回已有事件的研究窗口，比较其决策对象、关键行动和要回答的问题。停运通知、抢修进展和复通公告若共同回答一次中断如何恢复，归入同一行。后续独立裁决若改变了具体义务，且其形成或执行有材料可重建，才可另立并关联；仅换日期、地点、报道角度或分类不足以拆行。 |
| 同一设施或机构多次出现相似事件 | 比对前次是否持续、何时恢复，以及后一次是否有可辨认的新起点和处置过程。例如，抢修期间多次更新停运时长，仍属一次中断；恢复运行后又发生停运，且记录能区分两次影响和处置，则分别判断后一次是否值得入选。间隔天数、是否同年或是否有不同文号，都不足以单独判定。 |
| 多个小事件被合成一个大题目 | 对同类、同地或同期发生的事项，查原文是否把它们联系到同一次行动、调查或有明确边界的演变过程。若各案只共享行业背景，就分别判定，不能靠合并后的次数或损失取得资格。若后来确有一次覆盖多起事项的调查或召回，可围绕这次调查或召回本身判定。 |
| 一段市场或系统变化没有明确的单一决策者 | 明确受影响的市场或系统，用口径可比的记录定位变化窗口，并说明在此期间交易、融资、供给或服务怎样实际改变。只有一段涨跌曲线和事后选出的高低点，尚不足以说明独立研究价值。行动主体不清楚时，可以沿可观察的变化重建过程，成因留待查证。 |
| 事件已证实，但成因、损失或责任仍有争议 | 去掉争议断言，再看剩余事实能否独立满足入选条件。例如，中断和应急处置均有记录，原因未定，仍可研究中断与恢复；名称和范围也应围绕已证实的过程。若去掉传闻后只剩日常活动，就不能沿用原定题名或借争议热度入选。 |
| 原始通报被更正，或已执行的决定后来撤销 | 若发布方澄清原报事故并未发生，就停止以该事故为候选。误报若实际触发疏散等处置，可就经核实的处置另行判断。若决定确曾生效、后来才撤销，则按真实时序评估它在有效期间的影响。若更正只涉及数量，改用修订值，再判断剩余影响是否足以入选。 |

## 用已入选案例校准边界

| 历史事件 | 对新增候选的启示 |
| --- | --- |
| `event2994` · Nasdaq SIP Outage of 2013 | 中断与恢复可以发生在同一天。只要功能变化、影响对象和处置过程能够查证，短时事件也值得独立研究。 |
| `event1389` · U.S. Farmland Price Boom and 1980s Bust | 跨年的经济过程也可收录。将对象限定到美国农地市场，将问题限定到这一轮上涨、反转及调整，便有可研究的边界。 |
| `event2879` · Grindr National Security Divestment Order | 一项具体处置决定可以成为事件中心。可追踪决定针对什么对象、如何影响所有权及如何落实。 |
| `event197` · 2021 Texas Power Crisis；`event1703` · Winter Storm Uri Natural Gas Supply Crisis outside Texas | 同一天气过程可以引出不同研究对象。应分别界定得州电力系统失灵和跨境天然气供应中断；仅出现共同的风暴名称不足以判重。 |
| `event2995` · Saint-Gobain Sika Takeover Governance Battle | 研究对象是收购中的控制权争夺及其和解。另一宗收购若只有例行公告和预定交割日期，尚缺值得独立重建的转折；若公开记录显示治理争议改变了交易进程，就有了具体研究问题。 |
| `event2882` · Dee Bridge Collapse | 局部工程事故也可形成研究案例。可追踪失效涉及哪个工程对象、调查如何判断设计问题。普通维护通报若只更新施工时间，更适合作为背景材料。 |

## 如何作决定

对可能有研究价值、初搜却只有简讯的候选，用当事方、当地语言名称、正式编号或关键行动补查主管机构、当事方或档案中的原文。先核对候选指向哪一件事，再决定如何处理材料。同年、同机构的不同事项分别核对对象、行动和原文编号。身份存疑且有具体线索时暂存，记下待比对的已有 ID 和待查材料；定向补查后仍无法辨认事项、也没有后续线索时跳过。仅在确认对应关系后才把材料写入已有行。

地方性或较早的事件可用当地语言的会议记录、运行日志、调查报告或公开档案核实。能读到正文、定位材料并据此重建实际变化，就按相同标准评估；只有目录题名或摘要时，只采用其中实际载明的内容。事后发布的复盘可证明研究窗口内的行动。若任务明确要求还原“截至某日当时已知的信息”，用于该判断的证据须在该日已可获得，当时尚未核实的消息应保留其来源归属。

| 检索后的情况 | 处理 |
| --- | --- |
| 已确认是既有事项，或材料只补充其范围内的一个步骤 | 有新增且已核实的事实、定位或更正时更新已有行；材料完全重复时沿用现有记录。 |
| 是独立事项，实际影响有据、能据原文重建过程且已经查重 | 具备入选资格。选入本批并补齐主表必填项后才分配新增编号。同类已有案例可用于比较；候选无需证明其机制在全库首次出现。 |
| 已有证据显示实质影响，但重建所需的关键材料暂缺，且有具体追查线索 | 暂存在研究计划，写明缺口、可查的文书或发布方，以及何时值得重查，例如等待已公告的调查报告发布。取得材料后重新判定，暂存期间不计入新增数。 |
| 影响轻微、缺乏值得独立研究的变化，即使通报和报道齐全 | 跳过，不分配编号。类别仍有缺额时，继续寻找其他候选。 |
| 定向补查后只找到日期、标题、简讯或重复转述，无法用原文说明关键行动或状态如何演变 | 本轮不入选，不分配编号。只有已证实实质影响且有具体待查材料时才暂存线索；其余跳过。 |

例如，同为局部停水：只有计划检修通知和内容相同的转载，查不到实质影响或处置经过，就跳过。若主管部门的复盘能说明哪些社区供水受影响、为何启动应急送水、又如何分区恢复，则即使只涉及一座城镇，也有值得重建的过程。此例仅演示判定方法。批次材料不足时按实际入选数交付。

**合格候选多于本批可收录数时**，先遵守用户指定的选题范围，再从合格候选中优先选择能用原文回答明确研究问题、并补充实际覆盖缺口的事项，例如尚少有记录的处置方式。类别有缺额时仍逐案判定。已经核实、仅因批次容量或选题范围而留待后续的候选，可以在研究计划中注明原因，保留来源线索，不占编号、不计新增。后续采用前对照最新主表查重。本轮总数已达 10,000 条时，在现有计划下停止分配新编号。

不设统一的金额、伤亡、热度、持续天数、阶段数或报道篇数门槛。局部或持续中的事件可以入选，只要已发生的部分满足以上判断。结束日期、完整因果链及最终图可在后续研究中补全。示例沿用历史表中的选题，用于说明粒度；填写事实时仍按字段规范核对原文。
